# 0011: RAG answers, citations, guardrails

Status: accepted (defaults); thresholds pending the business evaluation set.

## Flow (`src/app/rag/service.py`)

1. Feature flag `rag`. Off means `503 UPSTREAM_UNAVAILABLE`, so the Java app falls back.
2. Guardrail on the question (denied patterns), then the **same `SearchService` as `/v1/search`**
   (rule 1: the access filter, the reranker and `mode_used` come for free).
3. Gate: if the reranker ran and the best score is below `rag.min_score`, the answer is
   `found: false, reason: low_relevance` and the LLM is not called. The gate is not applied to RRF
   scores because they have no absolute meaning. `min_score` stays 0 (off) until the evaluation set
   sets it.
4. Context (`rag/context.py`): at most `max_chunks` (8) chunks, near-duplicates dropped (word-triple
   Jaccard, `duplicate_similarity`), at most 3 per document, other documents first, cut to
   `context_token_budget` with the chunker's tokenizer. PII is masked in the passages first.
5. Prompt from `prompts/answer.v1.txt` (rule 11). Values are filled in one pass, so `{{...}}` in a
   document is never expanded.
6. Model call through `LLMClient` (in-house OpenAI-style server, or OpenAI behind `allow_external`),
   with a time limit and a circuit breaker.
7. `NOT_FOUND` becomes `found: false`. The model writes only `[n]`; the service maps numbers to
   `doc_id`, pages and a snippet from its own context list. An answer with no valid citation is
   **rejected** (`reason: unverified`) by default; `rag.on_bad_citations: flag` shows it with a
   warning. Numbers outside the context are removed from the text and reported as a warning.
8. PII masking and denied-answer patterns on the answer.

## Response

Additive to the HLD example: `reason`, `warnings`, `mode_used`, `prompt_version`.
`found: false` always comes with a reason (`not_found`, `low_relevance`, `no_context`, `unverified`,
`blocked`, `refused`).

## Streaming (`/v1/answer/stream`)

Everything that can fail before the first token (feature flag, search, rights, gate) answers with a
normal HTTP error. After that: `token` events, then `citations`, then `done` (or `error` if the model
breaks). `NOT_FOUND` is held back and never sent as a token. Source numbers that are not in the
context are dropped, and a marker split between pieces (`[` `1]`) is held. With PII masking on, text
is released sentence by sentence so a value is never cut in half.

Known limit: the citation check and the denied-answer check run on the full text. If they fail after
tokens were sent, `done` says `found: false` and the client must discard the streamed text. Streamed
usage is an estimate (4 characters per token).

## Guardrails and PII

In-house, regular expressions, no Presidio or NeMo (they need security approval as new dependencies):
e-mail, phone, card (Luhn), IBAN (mod 97), PAN, Aadhaar. This finds formats, not meaning, so test it
on real documents (with approval) and extend `rag/pii.py` where it misses. Prompt-injection tests
(`tests/unit/test_answer_service.py`) show that instructions inside documents stay data in the prompt
and that an answer that obeys them has no valid citation and is rejected. They cannot prove that a
real model resists injection: that needs the evaluation set.

## Not done here

- Second-pass claim check with a smaller model (HLD "high-risk use"): the eval judge covers
  measurement, not runtime.
- Neighbour chunks at sentence boundaries, answer caching, multi-turn chat (HLD "later").
- Real LLM and real model numbers: the in-process tests use a scripted fake.
